# 视频核对工具（VideoChecker）

面向**监控录像 / 视频文件**的质量核对工具：C# WinForms 单文件 exe，**零第三方运行时依赖**，
音视频分析用内置的 FFmpeg。支持批量检测本地文件、拉流检测 RTSP 摄像头，
并可选用本地视觉模型（Ollama）做画面内容理解。

- 编译：系统自带的 `csc.exe`（**不需要 Visual Studio**）✓
- 运行：Windows 7 / 10 / 11 + .NET Framework 4.x（系统自带）✓
- 界面：全代码构建（无设计器文件），19 套配色主题

---

## 功能

| 功能 | 说明 |
|---|---|
| **本地视频检测** | 音频完整性、视频完整性、音画同步、音频质量（电流麦/底噪/爆音）、AI 画面理解 |
| **RTSP 实时检测** | 拉流业务检测：帧率丢帧、码率稳定性、关键帧间隔、画面动态性、音频、拾音器、时间水印 |
| **AI 内容理解与文搜** | 视觉模型逐帧理解全片内容并读时间水印，支持关键词搜索定位画面（可选） |
| **AI 实时巡检** | 摄像头有变化才分析，异常自动告警（报警推图 / ONVIF 事件订阅 / 定时轮询三种方式） |
| **网络搜索摄像头** | ONVIF + SSDP 自动发现设备，自动试出各家不同的 RTSP 取流地址 |

判定原则：**总评不会优于任何单项结论** —— 出现 FAIL 就不会判成「通过」；
另有「关键项保护」可对黑屏/静音/花屏等致命问题一票否决。

### 长视频怎么做到不慢

- **CPU + GPU 同时解码**：长视频（全片模式）自动切成多段，一段走硬件解码、其余走软件解码，
  多进程并行，最后合并检测结果（实测约 2~3 倍加速）
- **实时进度**：解析 FFmpeg 的 `time=` 进度行，界面显示当前阶段、已处理时长与预计剩余时间
- **激进模式**（设置 → 性能）：硬件解码门槛降到 1 分钟、并行分段更多；
  开启后**全部 AI 理解会被停用** —— AI 推理和硬件解码会抢同一块显卡的显存
- **显卡可选**：自动检测本机有哪些 GPU 可用于硬件解码，可指定用哪一块

## 快速开始

### 1. 准备 FFmpeg

本仓库不含 FFmpeg（体积原因）。到 <https://ffmpeg.org/download.html> 下载 Windows 构建，
把 `ffmpeg.exe` 和 `ffprobe.exe` 放到 `vendor\ffmpeg\bin\` —— 详见
[`vendor/ffmpeg/bin/README.md`](vendor/ffmpeg/bin/README.md)。

> Windows 7 用户注意：请用 **2022-06-29 之前**的构建（更新版在 Win7 上启动即崩）。

### 2. 编译

双击 **`build.bat`**（或手动执行 `csc` 那条命令），产物在 `dist\video_checker_gui.exe`。

编译命令（脚本里就是这一条）：

```bat
%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe ^
  /target:winexe /optimize+ /platform:anycpu ^
  /out:dist\video_checker_gui.exe ^
  /r:System.dll /r:System.Core.dll /r:System.Drawing.dll ^
  /r:System.Windows.Forms.dll /r:System.Xml.dll /r:System.Security.dll ^
  /r:Microsoft.CSharp.dll ^
  /win32icon:assets\app.ico src\*.cs
```

### 3. 运行

把 `ffmpeg\bin\`（含两个 exe）放到 `video_checker_gui.exe` 同级目录，然后双击运行。

命令行模式（适合批处理 / 自动化）：

```bat
video_checker_gui.exe --cli D:\videos\test_samples
:: 结果写在 logs\cli_result.txt，退出码 0=通过 1=警告 2=失败 3=错误 4=无文件
```

## 用法要点

**本地检测**：左侧导航第一个图标 → 「浏览…」选文件或文件夹（也可直接拖进来）→
勾选检测内容 → 「开始检测」→ 「打开报告」（HTML + PDF）。

**RTSP 实时检测**：第二个图标 → 填流地址（如
`rtsp://admin:密码@192.168.1.64:554/Streaming/Channels/101`）→ 「添加/更新」或「导入 CSV」→
「开始分析」或勾选多路「开始轮巡」。
> 流列表会**加密保存**（Windows DPAPI），界面与报告里的密码一律打码 ✓

**AI 功能（可选）**：需要自己装 [Ollama](https://ollama.com) 并拉一个视觉模型
（如 `ollama pull qwen2.5vl:7b`），然后在「设置」页填地址和模型。

**检测模式**：`全片分析`（最准，长视频慢）/ `快速`（只采样前 60 秒）。

## 开屏密码

**默认不设密码**，首次进入会问一次要不要设置；密码以 PBKDF2 + 随机盐存储，文件里没有明文。

> ⚠ 这是**客户端锁**，作用是防误触、防随手打开，**不是安全边界**：
> 源码就在本仓库里，锁状态也存在本机。
> 要真正保护数据请用 Windows 账户权限或加密磁盘。

**忘记密码怎么办**（两步都要做）：

1. 删掉程序目录下的 `data\lock.dat`
2. 删掉注册表项：`reg delete "HKCU\Software\VideoChecker" /f`

> 只做第一步不行 —— 密码状态同时记在文件与注册表两处，只删文件会被判定为
> 「有人删锁试图绕过」，仍然要求密码。这是故意的（防绕过）。

**本项目不含任何万能密码 / 后门** —— 源码里没有硬编码的恢复密码。

## 已知限制

- 检测报告与归档视频是**明文文件**，密码锁不保护它们
- 混淆/加壳一类手段只能提高逆向成本，**挡不住动态调试**（本仓库发布的是源码）
- 50Hz 占比低于 -20dB 的弱交流声与正常人声重叠，拾音器检测分不出来
- 放弃用系统播放器做「从中间起播」（对监控素材的 H.265/大 GOP 定位不可靠），
  播放走的是关键帧连播
- AI 功能的抽帧与判定依赖本地视觉模型，模型能力直接决定结果质量
